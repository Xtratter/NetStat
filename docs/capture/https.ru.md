# Диагностика HTTPS

NetStat открывает отчёт локального прокси mitmproxy. В него попадают запросы
и ответы HTTP/1.x и HTTP/2, переданные ему совместимым клиентом. Сеанс ограничен
одним хостом и портом. Метка клиента задаётся вручную. Диагностика использует TCP
и явную настройку прокси в выбранном клиенте. HTTP/3 через QUIC в ней недоступен.

## Запуск в Termux

В окружении с `grun`, Python и утилитой `curl` скачайте официальный Linux arm64
архив mitmproxy. Выполняйте команды из каталога NetStat. Если `mitmdump` уже
доступен как обычная команда, для запуска хватит Python-скрипта без
`--glibc` и `--mitmdump`. [Установка mitmproxy](https://docs.mitmproxy.org/stable/overview/installation/)

```sh
mkdir -p .superpowers/mitmproxy
curl -fLo .superpowers/mitmproxy/mitmproxy.tar.gz https://downloads.mitmproxy.org/12.3.1/mitmproxy-12.3.1-linux-aarch64.tar.gz
tar -xzf .superpowers/mitmproxy/mitmproxy.tar.gz -C .superpowers/mitmproxy mitmdump
python tools/https_capture.py example.com --client curl --glibc --mitmdump .superpowers/mitmproxy/mitmdump
```

Скрипт покажет локальный адрес, выбранный хост и путь к публичной части
сертификата CA. Для контрольного запроса из второй вкладки Termux подставьте
напечатанный путь. `--cacert` задаёт доверие для этого запроса.

```sh
curl --noproxy "" --proxy http://127.0.0.1:8080 --cacert 'ПУТЬ-К-mitmproxy-ca-cert.pem' https://example.com/
```

Для другого клиента укажите в скрипте его метку и нужный хост. В клиенте
задайте явный HTTP-прокси `127.0.0.1:8080` и доверие к
`mitmproxy-ca-cert.pem`. Прокси проверяет сертификат настоящего сервера.
Клиенты с собственной политикой доверия могут отклонить соединение.
[Режим явного прокси](https://docs.mitmproxy.org/stable/concepts/modes/) ·
[Сертификаты mitmproxy](https://docs.mitmproxy.org/stable/concepts/certificates/)

## Остановка и просмотр

1. Нажмите Ctrl+C во вкладке прокси или дождитесь окончания сеанса. По
   умолчанию он длится до трёх минут. Скрипт прекратит прослушивание,
   удалит временный CA и напечатает путь к отчёту.
2. Передайте отчёт напрямую из Termux через меню «Поделиться».
   Подставьте путь, напечатанный скриптом, и выберите NetStat.

   ```sh
   termux-open --send --chooser --content-type application/vnd.netstat.https+json 'ПУТЬ-К-session.netstat-https.json'
   ```

   Доступный системному выбору файл можно открыть в самом приложении через
   **Захват → HTTPS → Открыть сеанс диагностики**.
3. Откройте диалог или используйте поиск по URL, заголовкам и тексту.
   Если запросы до прокси не дошли, список будет пустым. При наблюдаемых сбоях
   TLS NetStat покажет счётчики клиентской и серверной стороны.
4. Уберите настройки прокси и временное доверие в клиенте. Удалите отчёт,
   когда он больше не нужен. В нём могут быть токены и данные запроса.
   NetStat читает его в память и сбрасывает при выходе с экрана.

Предпросмотр ограничен 256 КиБ на тело. Прокси передаёт крупные тела потоком,
поэтому в отчёте могут остаться только заголовки. Объём отчёта ограничен 7 МиБ
данных диалогов.
